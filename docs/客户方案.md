## 1. 产品定位

CompriX 面向算力与 Token 现货交易场景，提供：

1. **客户侧**：可浏览的行情与询价入口  
2. **Broker 侧**：线下成交的履约与记账操作系统  

**产品原则：人谈机记。**  
商务洽谈、交付协调与资金往来在线下完成；系统负责记录状态、出具正式报价、跟踪订单进度、沉淀财务台账，并以合规方式呈现市场氛围。

本期明确不建设：自动撮合引擎、即时通讯、链上结算、自动支付、人工智能自动报价等能力。

---

## 2. 解决什么问题

| 角色 | 痛点 | CompriX 提供的能力 |
|------|------|-------------------|
| 采购客户 | 看不到货源与参考价，询价路径长，进度不透明 | 行情大厅、结构化询价、报价倒计时确认、订单进度可查 |
| Broker / 运营 | 单子散落在微信与表格中，SLA 难追踪，账目易乱 | 询价池与分配、报价发送、订单五态、应收应付与赔付记账 |
| 平台方 | 前台「空置」影响信任，又不能暴露真实成交明细 | 通告、热门 SKU、脱敏成交动态（人工审核发布） |

**体验目标（一句话）**

- 客户感知：**有货、有价、有人跟进、有进度**  
- Broker 感知：**单子进得来、时效看得见、报价发得出、账记得清**  
- 运营感知：每日约 15 分钟即可完成参考价、通告与动态维护

## 4. 客户前台能力

### 4.1 行情大厅（首页）

首页按**交易行情板**组织信息密度，而非品牌宣传落地页。

| 模块 | 说明 |
|------|------|
| 运营通告 | 展示当前生效的一条官方通告（可配置起止时间） |
| 交易台顶栏 | 品牌标识、实时时钟、LIVE 状态、询价入口 |
| 热门报价板 | 3～6 个热门 SKU：中位参考价、涨跌、价格区间；可进入详情或发起询价 |
| 市场脉搏 | 参考价更新日期、询价活跃提示、已发布成交动态条数 |
| 成交动态条 | 横向滚动展示已审核发布的脱敏成交信息 |
| 完整行情表 | 全部前台可见 SKU；支持 GPU / Token 筛选 |
| 服务说明 | 撮合方式、进度可追溯、对公结算等信任说明 |
| 询价引导 | 页底再次提供提交询价入口 |

**实时性约定（不做虚假人气）**

- 行情相关数据默认约每 30 秒自动刷新；浏览器标签页不可见时暂停  
- 展示真实同步时间与 LIVE 标识  
- **不展示**虚构在线人数、假聊天或虚假成交  

**参考价说明**：页面展示的低 / 中 / 高价格为市场参考区间，**不构成要约**；最终成交价以 Broker 发出的正式报价为准。涨跌以上一交易日同 SKU 中位价对比计算；无昨日数据时显示「—」。

### 4.2 SKU 详情

展示卖点、规格、当日价格区间与涨跌、近 30 日成交价格区间（若有）、交期说明，并提供询价入口。非公开或已下架 SKU 对外统一为不可用。

### 4.3 提交询价（两步）

1. **需求**：选择 SKU、数量、租用时长、期望交付日期；旁注展示「参考中位价 × 数量」仅供对照  
2. **联系**：姓名、公司、登录手机号（只读）、预算区间（选填）、备注  

时长按 SKU 计价单位提供标准档位（如按小时 / 按月 / Token 额度），避免自由文本歧义；特殊周期可选「其他」后补充说明。表单草稿保存在本机浏览器，刷新页面不丢失。

提交后系统记录来源页面，并设定约 6 小时内的首次响应时效目标（SLA），供后台识别超时风险。

### 4.4 我的工作台

- 待确认报价（含剩余有效时间倒计时）  
- 询价列表与订单列表  
- 列表约每 30 秒静默同步  

### 4.5 报价确认

客户可查看：成交价、交付信息、脱敏供应商名称、Broker 客户可见说明、报价剩余有效时间。  
可确认或拒绝；拒绝时可填写原因。报价自发送起默认 **24 小时**有效，超时后不可确认。

### 4.6 订单进度

订单确认后进入履约状态机。客户可见状态时间轴中，仅展示 Broker 标记为「客户可见」的进度说明；供应商真实名称与联系方式不对客户展示。

## 5. 管理后台能力

| 模块 | 能力摘要 |
|------|----------|
| 今日工作台 | 当日询价量、待处理询价、本月订单与成交额等关键指标 |
| 询价池 | 列表、筛选、分配 Broker；查看客户需求与 SLA 风险 |
| 报价 | 录入草稿 → 发送客户；支持客户可见说明；一询价单对应一有效报价 |
| 订单履约 | 五态推进；操作日志；附件上传；完成后可生成成交动态草稿 |
| 财务记账 | 应收 / 应付 / 赔付手工确认（线下收款，系统记账） |
| 行情与供给 | SKU（公开/热门/卖点/排序）、参考价、供应商主数据 |
| 运营配置 | 通告管理；成交动态审核发布（可调整区域、SKU 显示名、成交类型） |

账号体系：Admin 具备全量配置权限；Broker 可处理业务单据并维护运营向 SKU 字段（如热门、卖点），核心主数据变更由 Admin 管控。

## 6. 核心业务流程

```
客户浏览行情 → 提交询价
       ↓
Broker 认领 / 分配 → 线下沟通谈价
       ↓
录入报价（草稿）→ 发送客户（正式报价，24 小时有效）
       ↓
客户确认 ────────────────────────┐
       │                         │
       ▼                         ▼ 客户拒绝
自动生成订单                   询价结束
       ↓
待签约 → 待交付 → 待验收 → 待结算 → 已完成
       ↓
财务记账（收款 / 放款 / 赔付）
       ↓
（可选）审核发布脱敏成交动态至前台
```

### 6.1 状态定义

| 对象 | 状态 |
|------|------|
| 询价（RFQ） | 待处理 → 已报价 → 已确认 / 已拒绝 |
| 报价 | 草稿 → 待确认 → 已确认 / 已拒绝 / 已过期 |
| 订单 | 待签约 → 待交付 → 待验收 → 待结算 → 已完成；另支持已取消、已赔付 |

每次订单状态变更均留存操作日志（原状态、目标状态、备注、操作人）。

### 6.2 服务时效（SLA）建议口径

| 环节 | 建议对外口径 |
|------|----------------|
| 询价首次反馈 | 通常 2～6 小时 |
| 正式报价有效期 | 发送后 24 小时 |
| 未报价超时提示 | 后台按 4 小时 / 6 小时分级标识，便于 Broker 优先处理 |

## 7. 数据安全与脱敏

| 数据类型 | 客户前台 | 规则 |
|----------|----------|------|
| 供应商真实名称 / 电话 | 不展示 | 仅展示脱敏显示名或「平台优选供应商」 |
| 他人成交价格 / 公司信息 | 不展示 | 成交动态不含价格与客户身份 |
| 本人报价与订单金额 | 可展示 | 仅本人登录可见 |
| 区域信息 | 可展示 | 仅粗粒度：东部 / 南部 / 西部 / 北部 / 海外 |
| Broker 姓名 | 可展示 | 增强服务可信度 |
| Broker 电话 | 默认不展示 | 可按配置在订单阶段开放 |

成交动态由平台侧审核发布，不强制客户授权即可展示脱敏信息；发布前可编辑展示用区域、SKU 名称与成交类型，**禁止写入价格字段**。

接口层统一错误返回结构，不向客户端暴露系统堆栈；上传附件设大小限制；外部短信调用设超时控制。

## 8. 交付范围与分期建议

以下分期便于评审与排期；**当前演示环境已覆盖 Phase A / B 的主要能力**（以现场演示为准）。

| 阶段 | 主题 | 主要内容 |
|------|------|----------|
| **第一阶段** | 感知与询价体验 | 深色行情大厅、热门报价、通告、公开 SKU 过滤、SKU 详情、两步询价、工作台与报价倒计时 |
| **第二阶段** | 市场活跃与时效 | 参考价涨跌、脱敏成交动态（草稿 + 发布）、报价过期处理、大厅自动刷新与动态条 |
| **第三阶段** | 运营效率增强 | 参考价批量维护、拒绝原因枚举、客户可见进度说明增强、SKU 批量可见性等 |

**本期范围外（可后续立项）**

自动撮合、区块链 / 链上资产、支付宝等自动收款、站内 IM、供应商评分体系、多语言与独立 App、AI 自动报价助手、前台虚构活跃数据等。

## 9. 上线与运营准备清单

| 序号 | 事项 | 说明 |
|------|------|------|
| 1 | 热门 SKU 配置 | 建议不少于 6 个，含卖点、排序与当日参考价 |
| 2 | 全量公开 SKU 当日价 | 保证行情表可浏览 |
| 3 | 生效通告 | 至少 1 条业务向通告 |
| 4 | 成交动态 | 建议准备 3～5 条可发布样本（脱敏） |
| 5 | 服务与保障页 | 法务与服务口径已定稿 |
| 6 | 通知通道 | 短信模板按当地规范报备（若启用） |
| 7 | Broker 账号 | 建议不少于 3 个账号完成演练 |
| 8 | 数据洁净 | 前台不出现测试命名 SKU |
| 9 | 闭环演练 | 大厅 → 询价 → 报价 → 确认 → 订单全链路跑通 |

## 10. 成功衡量（建议）

上线后约 4 周内，建议跟踪：

| 指标 | 建议目标 |
|------|----------|
| 行情页至提交询价的转化 | 建立基线，并观察周环比 |
| 发送报价至客户确认的比例 | 不低于内测基线 |
| 热门 SKU / 通告 / 动态「有内容」的工作日占比 | ≥ 80% |
| 前台测试数据外泄 | 0 |

## 11. 风险与应对

| 风险 | 应对 |
|------|------|
| 缺少日常运营导致首页信息陈旧 | 明确运营清单与责任人；工作台提示「今日参考价未更新」 |
| 成交动态引发信息联想 | 粗粒度区域 + 人工审核发布 + 禁止展示价格 |
| 过期报价积压 | 定时将超时待确认报价标记为已过期 |
| 视觉风格调整影响使用习惯 | 全量切换前安排短周期内部试用 |

---

## 12. 演示建议路径

建议向客户按如下路径演示（约 10～15 分钟）：

1. **行情大厅**：热门报价板、涨跌、通告、成交动态、完整行情表  
2. **提交询价**：选择 SKU → 标准时长档位 → 联系信息 → 提交成功  
3. **管理后台**：询价分配 → 录入并发送报价（含客户可见说明）  
4. **客户确认**：倒计时展示 → 确认生成订单  
5. **订单与财务**：推进状态、查看日志、记账示意  
6. **运营**：发布一条脱敏成交动态，回到大厅观察更新

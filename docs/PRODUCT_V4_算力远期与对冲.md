## 1. 一句话定位（升级）

**CompriX 的长期目标，不是做一个「找卡中介系统」，而是做算力市场的价格发现与价格风险管理平台。**

近期能力仍是：**现货行情 + 询价成交协作（人谈机记）**。  
中长期能力演进为：**以可结算的远期合约，帮助 AI 公司锁定算力成本；以高频现金结算沉淀公允价格曲线；以少数实物交割通道承接真实算力需求。**

| 层次 | 定位表述 |
|------|----------|
| 今天（已落地 / 可演示） | 算力现货行情大厅 + Broker 成交操作系统 |
| 明天（要跑通的产品） | 算力远期合约协作与差价结算（对冲工具） |
| 后天（网络效应） | 合约越多 → 结算价 / 远期曲线越准 → 吸引更多对冲与成交 |

## 2. 为什么要做远期，而不只做询价

### 2.1 客户真实诉求

以「AI 创业公司计划 6 个月后上线新产品」为例：

- 今天需要的不是立刻买断一批卡，而是**锁定 6 个月后的算力成本**。
- 若只提供现货询价，客户无法管理「价格上涨」风险；若强行现在买断，又造成资金与产能错配。

因此，平台必须从「撮一单现货」升级到「管理一段时间的价格风险」。

### 2.2 两种结局，一种成本

约定远期锁定价格为 **X**，到期参考结算价为 **S**（由平台价格指数给出）。

| 情形 | 市场变化 | 现金结算结果 | 客户实际获得算力的综合成本 |
|------|----------|--------------|---------------------------|
| 情况一 | 涨价，S = 1.5X | 卖方补偿买方 **0.5X** | 客户用补偿款按市价购入，综合仍约 **X** |
| 情况二 | 跌价，S = 0.7X | 买方补偿卖方 **0.3X** | 市价更便宜，加上已付差价，综合仍约 **X** |

这就是 **现金结算（Cash Settlement）**：结算的是差价，不强制搬迁算力资源。  
绝大多数交易应走这条路径——平台首先是**价格对冲工具**，其次才是算力交付通道。

### 2.3 极少数需要「真要用卡」

当客户到期确实需要算力跑训练 / 推理时，走 **实物交割通道**：

- 平台提前与润泽等算力商约定交割合作；
- 合约到期且选择实物交割时，由交割通道方按合约约定提供算力；
- 对算力商而言，这是新增销售渠道，并可提前锁定需求节奏。

**结构目标（产品原则，非监管承诺）：**

- **≥ 90%** 合约以现金结算完结（赌的是价格、管的是风险）；  
- **≤ 10%** 走实物交割（真的要算力）；  
- 跑通的合约越多，价格指数与远期曲线越可信。

## 3. 与当前项目的关系（务实衔接）

当前 CompriX（V3）已具备：

- 公开行情与参考价（低 / 中 / 高、涨跌）  
- 询价 → 报价 → 确认 → 订单履约 → 财务记账  
- 脱敏成交动态、通告、运营配置  
- 「人谈机记」——线下谈、线上记  

这不是弯路，而是远期市场的**地基**：

| V3 现货能力 | 对 V4 远期的价值 |
|-------------|------------------|
| 每日参考价与涨跌 | 价格指数的原始输入 |
| 真实询价 / 成交（含脱敏发布） | 曲线校准样本，避免「空转假价」 |
| Broker 履约与财务台账 | 差价结算、保证金、交割指令的运营骨架 |
| 供应商主数据 | 交割通道（如润泽）准入与配额管理 |
| 客户账户与订单 | 合约持仓、结算账单、交割申请的主体 |

**结论：** V4 不是推倒重来，而是在现货协作之上，增加「合约生命周期 + 结算价 + 现金/实物双路径」。

## 4. 产品原则（V4 锁定）

1. **先对冲，后交割**  
   默认现金结算；实物交割是可选增强，不是主路径。

2. **先有可信价格指数，再谈大规模合约**  
   没有可解释、可审计的结算价源，远期只会变成对赌纠纷。

3. **合约跑通优先于自动撮合**  
   前期允许 Broker / 做市协助撮合与确认；自动连续竞价可后置。与 V3「不做自动撮合引擎」不冲突——V4 前期仍是「半人工合约台」。

4. **真实交易校准曲线，禁止空转造假**  
   延续 V3：不以虚构人气制造热闹；曲线置信度来自可核验的成交、询价与交割样本。

5. **合规表述克制**  
   对外优先称「算力价格风险管理 / 远期合约协作平台」，审慎使用「交易所」一词，直至牌照、规则与资金托管方案明确。产品能力上对标交易所的价格发现与结算结构，商务与法务口径单独评审。

6. **交割通道可插拔**  
   润泽等为第一批交割服务商，模型上支持多通道、多地域、多 SKU 族。

## 5. 目标用户与核心场景

### 5.1 买方（Hedger）

- AI 创业公司、模型训练团队、推理业务方  
- 诉求：锁定未来 N 个月 GPU / Token 成本，平滑预算  

### 5.2 卖方（Hedger / 供给方）

- 算力商、机房、渠道商  
- 诉求：锁定未来销量与价格下限，平滑产能利用  

### 5.3 平台与 Broker

- 维护指数、组织合约、监督结算、安排交割  
- 前期以半人工运营保证每笔合约「跑得通、算得清、交得了」  

### 5.4 关键路径（用户故事）

> 某 AI 公司预计 6 个月后需要一批 H100 包月算力。  
> 1）在 CompriX 查看该 SKU 现货参考价与远期报价曲线；  
> 2）买入一份 6 个月到期、锁定价格 X 的远期合约（约定现金结算为主）；  
> 3）到期日平台公布结算价 S；  
> 4a）多数情况：完成差价结算，客户自行在现货市场采购；  
> 4b）少数情况：客户申请实物交割，平台向润泽通道下发交割指令，按合约条件交付。

## 6. 产品能力地图（分层）

```
┌─────────────────────────────────────────────────────────────┐
│ L4  市场曲线与风控仪表盘（成交密度 → 曲线置信度）              │
├─────────────────────────────────────────────────────────────┤
│ L3  实物交割通道（交割申请 · 通道配额 · 履约验收）             │
├─────────────────────────────────────────────────────────────┤
│ L2  远期合约与现金结算（开仓 · 持仓 · 到期结算 · 差价账单）     │
├─────────────────────────────────────────────────────────────┤
│ L1  算力价格指数（日结算价 · 成分与权重 · 争议复核）           │
├─────────────────────────────────────────────────────────────┤
│ L0  现货行情与成交协作（V3 已具备：询价/报价/订单/财务/动态）   │
└─────────────────────────────────────────────────────────────┘
```

### 6.1 L0 — 现货基座（巩固）

继续强化：行情板质量、参考价更新纪律、询价转化、脱敏成交样本、供应商与财务台账。  
**开发目标：** 让每一笔现货成交都能反哺指数与曲线，而不是停留在「接单后台」。

### 6.2 L1 — 算力价格指数（Price Index）

为每个可交易标的（如「华东 H100 包月」「某规格 Token」）定义：

| 要素 | 产品要求 |
|------|----------|
| 成分 | 参考价、脱敏成交、合格询价中位等可配置权重 |
| 频率 | 至少日频结算价；关键标的可扩至更细粒度 |
| 发布 | 公开可读、可回溯历史、可导出审计 |
| 争议 | 异常跳变熔断、人工复核、公布规则 |

没有 L1，就没有可靠的「情况一 / 情况二」中的市场价 S。

### 6.3 L2 — 远期合约与现金结算（核心要跑通）

最小可行合约要素：

| 字段 | 说明 |
|------|------|
| 标的 | 锚定指数成分对应的 SKU / 规格族 |
| 到期日 | 如 T+180 日 |
| 合约价 X | 开仓锁定的远期价格 |
| 数量与单位 | 卡月、卡时、Token 包等 |
| 结算方式 | 默认现金结算；可选实物交割（需资格） |
| 结算价 S | 到期日指数结算价 |
| 差价 | 多头：(S−X)×数量；空头相反（符号以合约规则为准） |

后台需支持：开仓登记 → 持仓管理 → 到期批量结算 → 差价账单 → 收付款确认（可先沿用 V3「人记账、线下款」）。

### 6.4 L3 — 实物交割通道

| 能力 | 说明 |
|------|------|
| 通道准入 | 润泽等算力商签约、可交割 SKU、区域、SLA |
| 交割申请 | 到期前窗口内，持仓方申请实物；平台审核 |
| 交割指令 | 生成对通道方的交付工单（价格按合约 X，细则合同化） |
| 履约闭环 | 开通、验收、异常赔付；与现货订单状态机可复用思想 |
| 比例监控 | 实物交割占比仪表盘，防止「名义对冲、实质全交割」失控 |

### 6.5 L4 — 曲线与置信度

- 展示：现货曲线、远期报价点、历史结算价  
- 置信度：样本成交笔数、持仓量、买卖价差、交割占比  
- 运营 KPI：**跑通合约数 ↑ → 曲线置信度 ↑ → 新开仓意愿 ↑**（正向飞轮）

## 7. 信息架构建议（相对 V3 的增量）

### 7.1 客户前台增量

| 页面 / 模块 | 说明 |
|-------------|------|
| 价格指数页 | 标的列表、日结算价、历史走势 |
| 远期曲线 / 合约列表 | 可交易到期月、指示价、持仓规则摘要 |
| 我的持仓 | 锁定价 X、数量、到期日、预估浮动盈亏（基于最新指数） |
| 结算账单 | 差价明细、支付/收款状态 |
| 交割申请 | 仅对开通实物权限的账户展示 |

现货「行情大厅 + 询价」保留为获客与样本来源入口，不削弱。

### 7.2 管理后台增量

| 模块 | 说明 |
|------|------|
| 指数管理 | 成分、权重、发布、熔断与复核 |
| 合约品种 | 标的、到期、最小数量、保证金规则（可先简化） |
| 合约台 / 持仓 | 开仓确认、双边对手方、状态 |
| 结算中心 | 到期批次、差价计算、账单、对账 |
| 交割通道 | 服务商、配额、工单、验收 |
| 曲线与风控看板 | 成交密度、交割占比、异常预警 |

Broker 角色从「只跟现货单」扩展为「合约生命周期运营官」。

## 8. 开发目标与分期（建议）

> 原则：**每一期都能对外讲清价值，并留下可度量的「跑通」样本。**

### 阶段 0 — 现货加固（0～1 个月，基于 V3）

**目标：** 价格样本干净、可运营、可演示。

- 热门 SKU、通告、脱敏动态、参考价更新 SOP 固化  
- 现货闭环稳定；财务台账可对账  
- 输出：合格「日参考价序列」与脱敏成交样本库  

**里程碑指标：** 工作日参考价覆盖率、前台 0 测试脏数据、现货闭环演示成功率。

### 阶段 1 — 价格指数 MVP（1～2 个月）

**目标：** 给出可解释的日结算价 S。

- 1～3 个标的指数（建议从最活跃 GPU 包月开始）  
- 发布、历史、异常复核流程  
- 与现货参考价、成交样本打通  

**里程碑指标：** 指数连续发布天数、复核工单闭环时长、规则文档对客可读。

### 阶段 2 — 远期合约 + 现金结算试运行（2～4 个月）★ 战略核心

**目标：** 完整跑通「锁定 X → 到期按 S 现金结算」最小闭环。

- 合约开仓（可先 Broker 协助双边确认）  
- 持仓与到期结算批次  
- 差价账单 + 线下收付确认（复用财务记账思想）  
- 前台：持仓、预估盈亏、结算结果  

**里程碑指标：**

- 成功完结的现金结算合约笔数（北星）  
- 结算差错率 → 0  
- 参与试运行的买方 / 卖方机构数  

**验收故事：** 用文档中的「涨到 1.5X / 跌到 0.7X」各至少跑通 1 笔沙盘 + 1 笔真实试结算。

### 阶段 3 — 实物交割通道（并行或紧随阶段 2）

**目标：** 少数真实用卡需求可交割，且占比可控。

- 至少 1 家交割通道（如润泽）打通工单  
- 交割申请窗口、审核、履约验收  
- 交割占比监控（目标结构：实物 ≤ 10%）  

**里程碑指标：** 交割成功率、交割 SLA、实物占比。

### 阶段 4 — 曲线飞轮与效率（其后）

- 多到期月、多标的曲线  
- 保证金 / 限额等风控增强（按合规节奏）  
- 在规则清晰后再评估自动撮合、更多做市方接入

## 9. 北星指标与过程指标

| 类型 | 指标 | 含义 |
|------|------|------|
| 北星 | **现金结算完结合约数（月）** | 「对冲工具」是否真的在被使用 |
| 质量 | 结算差错率、争议率 | 能不能算得清 |
| 结构 | 实物交割占比 | 是否仍以现金结算为主 |
| 飞轮 | 指数成分样本量、远期曲线买卖价差 | 曲线是否越来越准、越来越好用 |
| 基座 | 现货询价转化、参考价更新率 | L0 是否持续输血 |

**产品口号（对内）：**  
*跑通的合约越多，价格曲线越准；曲线越准，越有人愿意开仓。*

## 10. 关键设计要点（避免做成「空壳对赌」）

1. **结算价必须先于大规模营销合约**  
   先公开指数规则，再邀约试运行客户。

2. **现金结算默认，实物交割需白名单**  
   防止交割通道被挤兑；也符合「90% / 10%」结构目标。

3. **差价账单与现货订单分账**  
   对冲损益 ≠ 算力采购订单；财务与客户认知都要分开。

4. **沙盘 / 模拟盘可先于真钱**  
   用历史指数回放演练「1.5X / 0.7X」场景，降低教育成本。

5. **法务与资金流单列门禁**  
   保证金、托管、适当性管理不在本技术稿展开，但阶段 2 上线前必须有书面方案。

## 11. 范围边界（本期明确）

| 要做 | 暂缓 |
|------|------|
| 指数、远期合约台、现金结算账单 | 全自动连续竞价撮合 |
| 交割通道工单（少数量产） | 多交易所互通、链上结算 |
| 曲线与置信度展示 | 面向散户的高杠杆投机产品 |
| 在 V3 现货上持续获客与样本 | 虚构成交与虚假曲线 |

## 12. 对客户怎么讲（沟通口径）

**短版：**  
CompriX 先帮你看清算力现货价格、高效完成询价成交；进一步帮你用远期合约锁定未来成本——大多数情况只结算差价，真正要卡时再走交割通道。合约跑得越多，价格越准，你的预算越可控。

**与竞品差异（建议表述）：**  
不是又一个「算力黄页」或纯中介 CRM，而是奔着**可结算的价格风险管理**去建设；现货协作是入口，远期与结算才是护城河。

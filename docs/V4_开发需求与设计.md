## 3. 多角色 × 链路 Review（结论摘要）

| 角色 | 主链路 | 原方案能否跑通 | 缺口 → 补全 |
|------|--------|----------------|-------------|
| 买方（对冲客户） | 看 S → 被开仓 → 确认 → 持仓盯盈亏 → 到期账单应收/应付 | 主路径可 | 缺「待确认」醒目入口与通知；账单文案须写清方向；无意向入口（接受：Broker 线下谈后开仓） |
| 卖方（对冲供给） | 同上（空头） | 易混 | **卖方必须是 User**，不能只用 Supplier；与交割通道方角色分离 |
| Broker | 开仓 → 催确认 → 批结算 → 确认收付 | 可 | 单边长期不确认会卡死 → **确认超时自动 cancelled**；允许 **代理确认**（留痕+备注，人谈机记） |
| Admin/运营 | 日更 mid → 生成/发布 S → 异常复核 | 可 | **已用于结算的 print 禁止改价/撤销发布**；工作台要能看到待发布/待结算数 |
| 交割通道（润泽） | 收工单 → 供算力 | M007 才做 | 首期无通道门户，工单由 Broker 线下同步；须定义 **交割申请窗口** |
| 平台/合规 | 试运行 | 门禁有 | 结算瞬间 **账单冻结 S/X/qty/amount**；不做保证金系统但文档门禁保留 |

**对设计目标的判断：**

- 「现金结算对冲、先有 S 再锁 X」——原 M005→M006 **方向正确，能满足**，但须补确认超时、结算冻结、卖方账户与通知，否则试运行会卡单或扯皮。  
- 「跑通越多曲线越准」——北星看板不应拖到 M008，**M006 就要在 Dashboard 露出完结合约数**。  
- 「≤10% 实物」——M007 做占比即可；M006 阶段所有新仓默认 `settle_mode=cash`。

## 4. 开发需求（必做）

### 4.1 阶段 A — 价格指数（先有 S）

| ID | 需求 | 验收 |
|----|------|------|
| A1 | 定义指数标的（先 1 个，锚定 1 个 SKU） | Admin 可建/改；前台可列表 |
| A2 | 每个交易日产出结算价 `S`（首发 = 当日锚定 SKU `price_mid`；可人工覆写） | 历史可查；**指数规则一页纸**对客可读 |
| A3 | 环比跳变超 ±20%（相对上一 **published**）→ `pending_review`；确认后发布 | **未发布不可用于结算** |
| A4 | 某日 print 一旦被写入任一 `settlement_bills`，禁止改价与取消发布 | 接口拒绝并提示「已用于结算」 |

### 4.2 阶段 B — 远期 + 现金结算 ★

| ID | 需求 | 验收 |
|----|------|------|
| B1 | Broker 登记远期：买方 User、卖方 User（`buyer_id ≠ seller_id`）、标的、qty、X、到期日；默认现金；进入 `pending_confirm` | 校验双方均为可登录用户 |
| B2 | **双边确认**：买方/卖方在前台确认；**Broker 可代理确认**（`proxy_confirm` + `note` + operator_id） | 齐后 → `open`；状态机见 §5.2 |
| B3 | **确认超时**：开仓时写 `confirm_deadline_at`（默认 +72h）；超时仍 `pending_confirm` → `cancelled`（批任务或结算前扫描） | 沙盘可测 |
| B4 | 客户「我的持仓」：待确认 / 持仓中；按最新 published S 显示浮动盈亏（标注「非最终结算」） | 仅本人（买方或卖方）可见 |
| B5 | 到期批结算：取到期日 published S，否则最近 published 并记 `settle_price_date`；全无则该笔跳过并记原因 | 涨 1.5X / 跌 0.7X 可演示 |
| B6 | 生成 `settlement_bills`（金额快照不可变）；Broker 确认已收/已付 | **不写入 orders** |
| B7 | 通知钩子（复用 notify）：待确认、已生效、已出账单 | 开发环境写日志即可 |
| B8 | Admin Dashboard：现金结算完结合约数、待确认数、今日待发布指数 | 北星可见 |
| B9 | 功能测试 + 沙盘脚本 +《结算规则》一页纸 | 全绿；真实测试账号跑通 1 笔（非对外真钱） |

### 4.3 阶段 C — 实物交割（M007）

| ID | 需求 | 验收 |
|----|------|------|
| C1 | 交割通道：supplier + sku | ≥1 条 seed |
| C2 | `delivery_whitelists` 按账户开通；默认全关 | |
| C3 | **申请窗口**：`expiry_date` 前 **T-7～T-0**（含到期日当日 15:00 前可配）；仅 `open`+白名单+默认仍为现金意向时可申请改实物 | 窗口外拒绝 |
| C4 | 审核通过 → `delivery_orders`；可选创建现货 order；合约 → `delivered`（不再现金结算） | |
| C5 | 实物占比 = delivered / (settled+delivered) | Dashboard 一行 |

### 4.4 明确不做

自动撮合、客户自助挂单、保证金自动划扣、提前平仓/转让、多腿组合、通道方独立门户、散户杠杆。

> **法务/资金门禁（非开发，卡对外真钱）：** 试运行对外前须有书面资金流与适当性方案。

## 5. 设计方案

### 5.1 主流程

```
参考价(日) ──► 指数日结 S（可覆写 / 跳变复核 / 发布）
                    │
Broker 开仓 ──► pending_confirm ──►（双方或代理确认）──► open（锁价 X）
         │                                    │ 到期
         └── 超时 → cancelled          ┌──────┴──────┐
                                       ▼             ▼
                                 现金结算          实物交割（窗口+白名单）
                                 账单快照          工单 → 通道（线下协同）
                                       │
                                 线下收付 + 后台确认
```

### 5.2 合约状态机

```
draft（可选，保存未提交）
  → pending_confirm   # Broker 提交开仓
  → open              # 双边确认齐
  → settled           # 现金结算出账
  → delivered         # 实物交割完成
  → cancelled         # 超时未确认 / Broker 作废（仅 pending_confirm）
```

非法迁移一律拒绝（如 `settled` 不可再交割）。

### 5.3 数据模型

```
price_indices       # id, code, name, sku_id, status, jump_threshold_pct(default 20)
index_prints        # id, index_id, date, settle_price, source, status(draft|pending_review|published)
                    # UNIQUE(index_id, date)

forward_contracts   # id, index_id, buyer_id, seller_id, qty, unit, strike_price X,
                    # expiry_date, settle_mode(cash|physical), status, broker_id,
                    # buyer_confirmed_at, seller_confirmed_at,
                    # buyer_confirm_by, seller_confirm_by,   # user_id，代理时为 broker
                    # confirm_deadline_at, cancel_reason

settlement_bills    # id, contract_id, settle_date, settle_price S, settle_price_date,
                    # strike X, qty, amount, pay_direction(seller_to_buyer|buyer_to_seller),
                    # pay_status(pending|done), confirmed_by, confirmed_at
                    # 创建后字段只读

delivery_channels   # id, supplier_id, sku_id, name, active
delivery_whitelists # id, user_id, approved_by, active
delivery_orders     # id, contract_id, channel_id, status(pending|approved|done|rejected),
                    # order_id null, note
```

差价（多头买方）：`amount = (S - X) * qty`  
- `amount > 0` → `seller_to_buyer`  
- `amount < 0` → `buyer_to_seller`（展示用绝对值 + 方向）

### 5.4 API

**Customer**

```
GET  /indices
GET  /indices/:id/prints?from=&to=
GET  /forwards                         # 我是买方或卖方
POST /forwards/:id/confirm
GET  /settlement-bills
POST /forwards/:id/delivery-request    # 白名单+窗口
```

**Admin**

```
CRUD /indices
POST /indices/:id/prints
POST /indices/:id/prints/:date/publish
POST /forwards                         # → pending_confirm
POST /forwards/:id/proxy-confirm       # body: side=buyer|seller, note
POST /forwards/:id/cancel              # 仅 pending_confirm
GET  /forwards
POST /forwards/settle-batch
POST /forwards/expire-confirms         # 超时取消（亦可挂 jobs）
POST /settlement-bills/:id/confirm-pay
CRUD /delivery-channels
CRUD /delivery-whitelists
POST /delivery-orders/:id/approve|complete
GET  /dashboard                        # 扩展北星字段
```

### 5.5 前端页面

| 端 | 页面 | 说明 |
|----|------|------|
| 客户 | `/indices` | 指数与历史 S |
| 客户 | `/forwards` | Tab：待确认 / 持仓中；浮动盈亏脚注 |
| 客户 | `/bills` | 应收/应付文案 + 状态 |
| 后台 | 指数 | 生成、覆写、发布、已锁定提示 |
| 后台 | 合约台 | 开仓（选买卖双方 User）、代理确认、作废、批结算 |
| 后台 | 结算 | 账单确认 |
| 后台 | Dashboard | 完结合约数、待确认、待发布指数 |
| 后台 | 交割 | M007：通道、白名单、工单 |

### 5.6 与现货边界

- 远期账单不进 `orders`（除非交割主动建履约单）。  
- Supplier ≠ 合约卖方；卖方要种子/运营开 customer 账号。  
- 现货大厅继续喂 `reference_prices`。

## 8. 验收故事

1. **涨价现金：** X=100，S=150 → 买方应收 50×qty → 确认收款。  
2. **跌价现金：** X=100，S=70 → 买方应付 30×qty → 确认付款。  
3. **超时：** 单边不确认超过 72h → cancelled。  
4. **代理确认：** Broker 代卖方确认并留 note → open。  
5. **结算锁定：** 已出账单的 S 不可再改 index_print。  
6. **实物（M007）：** 白名单 + 窗口内申请 → 工单完成；占比可查。

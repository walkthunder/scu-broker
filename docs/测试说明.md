## 1. 怎么跑

```bash
docker compose up -d mysql   # 若本地库未起
cd apps/api
npm run db:seed              # 推荐：干净种子账号与指数
# 另开终端：FRD_SCHEDULER=0 npm run dev
npm run test:functional
```

种子账号见根 [README.md](../README.md)（buyer / seller / admin / partner）。

沙盘（远期现金推演，非套件）：`npm run sandbox:forward`。

## 2. 用例编号约定

| 前缀 | 含义 |
|------|------|
| `R-AUTH-*` / `R-P0-*` / `R-P1-*` | 现货鉴权与主链路 |
| `R-GAP-*` / `R-ACCEPT-*` / `R-INFRA` | 缺口约定、验收点、基建 |
| `V3-*` / `V4-*` | 行情运营 / 指数·远期·交割 |
| `FR-*` | 硅元引擎 FRD 核心 |
| `PAGE-*` | **三端页面接口补全**（`16-page-apis.js`） |

文件映射：

| 文件 | 域 |
|------|-----|
| `01`–`09` | 鉴权、主数据、参考价、RFQ、报价、订单、财务、附件、看板安全 |
| `10`–`11` | V3 行情 / 运营通告成交动态 |
| `12`–`14` | 指数、远期结算、实物交割主路径 |
| `15-frd-core.js` | FRD 引擎、账本、挂单、权益、作业、伙伴申请 |
| `16-page-apis.js` | 页面曾缺测的关键接口（预售自助、出金、做市、伙伴台、CRM 等） |

## 4. 仍建议手工 / 后续补测的缺口

优先级 **P1**（演示前必点通）与 **P2**（完整度）。

| 优先级 | 接口 / 场景 | 原因 |
|--------|-------------|------|
| P1 | 交割意愿 `POST /frd/forwards/:id/delivery-intent` | 依赖到期前 N 天窗口，套件难固定日历 |
| P1 | 权益行权 `POST /frd/rights/:id/exercise` | 依赖窗内 open 持仓与现货 S |
| P1 | 交割驳回 / 开始 / 对账 / 违约 | 主路径只测批准→完成 |
| P1 | 伙伴交割凭证 multipart 上传 | 需真实文件流 |
| P2 | 账单 `confirm-pay`、远期 Broker `cancel` | 有相关旁路，缺页面同名断言 |
| P2 | 渠道成交凭证上传、DealFeed 删除 | UI 低频 |
| P2 | `/admin/customers` 列表、供应商 PUT | 被其它用例间接依赖 |

手工冒烟可按 [交付功能说明.md](./交付功能说明.md) 30 分钟脚本执行，并勾选该文档 §6。

## 5. 覆盖统计（页面接口维度）

对 views 中约 **119** 条规范化路径统计（通配合并后）：

| 指标 | 约数 |
|------|------|
| 套件已直接/等价覆盖 | ~70%+（含 `16-page-apis` 后；以当次 `test:functional` 为准） |
| 仍属缺口或仅冒烟 | §4 表中项 |
| 用例总数 | `01`–`16` 合计（运行日志 `Running N functional cases`） |

**说明：** 自动化是 API 契约与主链路回归，**不替代**浏览器端交互、权限边界与双人复核「两个真人账号」演示。

## 6. 新增页面相关用例后如何维护

1. 前端页面新增 `api('/...')` → 同步更新本文件 §3 矩阵一行。  
2. 能稳定断言的写路径 → 优先补进 `16-page-apis.js`（或按域拆文件），打 `PAGE-*` 标签。  
3. 强依赖日历/文件/双人的 → 记入 §4，演示清单保留手工步骤。  
4. 提交前：`da standards scan` + `npm run test:functional` 全绿。

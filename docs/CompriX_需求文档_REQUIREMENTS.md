## 1. 文档概述

### 1.1 项目背景
CompriX 面向 GPU / Token 算力现货交易场景，定位为「人谈机记」的 Broker 成交协作平台。商务洽谈、交付协调与资金往来在线下完成；系统负责记录状态、出具正式报价、跟踪订单进度、沉淀财务台账，并以合规方式呈现市场氛围。

### 1.2 本期范围边界
**明确本期不建设：**
- 自动撮合引擎
- 即时通讯（IM）
- 链上结算 / 区块链资产
- 自动支付（支付宝/微信自动收款）
- AI 自动报价助手
- 前台虚构活跃数据（假在线人数、假聊天、假成交）

### 1.3 术语表

| 术语 | 说明 |
|------|------|
| SKU | 算力商品单元，含 GPU 型号、Token 额度、计价单位等 |
| RFQ | Request for Quotation，客户询价单 |
| Broker | 平台业务人员，负责询价跟进、报价、订单履约 |
| Admin | 平台运营管理员，负责系统配置、主数据维护、审核 |
| SLA | Service Level Agreement，服务时效约定 |
| 参考价 | 市场参考区间（低/中/高），不构成要约 |
| 成交动态 | 经审核发布的脱敏成交信息，用于前台展示市场氛围 |

## 5. 状态机定义

### 5.1 询价（RFQ）状态机

```
待处理 → 已报价 → 已确认
              ↘ 已拒绝
```

| 状态 | 说明 |
|------|------|
| 待处理 | 客户提交后初始状态 |
| 已报价 | Broker 发送正式报价后 |
| 已确认 | 客户确认报价，自动生成订单 |
| 已拒绝 | 客户拒绝报价，询价结束 |

### 5.2 报价状态机

```
草稿 → 待确认 → 已确认
            ↘ 已拒绝
            ↘ 已过期
            ↘ 已失效（新报价覆盖）
```

| 状态 | 说明 |
|------|------|
| 草稿 | Broker 录入中，客户不可见 |
| 待确认 | 已发送给客户，等待确认 |
| 已确认 | 客户确认，关联订单生成 |
| 已拒绝 | 客户拒绝 |
| 已过期 | 超过 24 小时未确认 |
| 已失效 | 同一询价单新报价发送后旧报价状态 |

### 5.3 订单状态机

```
待签约 → 待交付 → 待验收 → 待结算 → 已完成
   ↓                                    ↑
已取消 / 已赔付 ────────────────────────┘
```

| 状态 | 说明 |
|------|------|
| 待签约 | 客户确认报价后初始状态 |
| 待交付 | 合同/协议签署后 |
| 待验收 | 算力交付后，等待客户验收 |
| 待结算 | 验收通过后，等待财务结算 |
| 已完成 | 财务结算完成 |
| 已取消 | 订单取消 |
| 已赔付 | 发生赔付后终止 |

## 6. 数据模型（核心实体）

### 6.1 实体关系概要

```
用户（客户 / Broker / Admin）
  └── 询价单（RFQ）
        └── 报价单（Quote）
              └── 订单（Order）
                    └── 财务记录（Finance）
                    └── 操作日志（Log）
                    └── 附件（Attachment）

SKU（商品单元）
  └── 参考价（ReferencePrice）
  └── 供应商（Supplier）

运营内容
  └── 通告（Announcement）
  └── 成交动态（DealFeed）
```

### 6.2 核心字段约束

| 实体 | 核心字段 | 约束 |
|------|---------|------|
| 用户 | 手机号 | 唯一，前台登录凭证 |
| 询价单 | SKU、数量、时长、期望交付日期 | 数量 > 0；时长非空 |
| 报价单 | 成交价、有效期、供应商 ID | 有效期默认 24 小时 |
| 订单 | 关联报价单、当前状态 | 状态严格按状态机流转 |
| SKU | 名称、规格、计价单位、公开状态 | 名称前台不可出现测试命名 |
| 成交动态 | 区域、SKU 显示名、成交类型 | 禁止存储价格字段 |

## 7. 接口规范（概要）

### 7.1 统一响应结构

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

- `code = 0` 表示成功，非 0 表示业务错误
- 错误时不暴露堆栈信息

### 7.2 核心接口清单

| 接口 | 方法 | 说明 |
|------|------|------|
| /api/market/overview | GET | 行情大厅聚合数据 |
| /api/market/skus | GET | SKU 列表与筛选 |
| /api/market/sku/:id | GET | SKU 详情 |
| /api/rfq | POST | 提交询价 |
| /api/rfq/my | GET | 我的询价列表 |

## 8. 验收标准（MVP 基线）

### 8.1 功能验收

| 验收项 | 通过标准 |
|--------|---------|
| 行情大厅 | 热门 SKU、通告、成交动态、完整行情表正常展示；30 秒刷新有效 |
| 询价流程 | 客户可完整提交询价；表单草稿本地保存有效 |
| 报价流程 | Broker 可分配、录入、发送报价；客户可确认/拒绝 |
| 订单流程 | 确认报价后自动生成订单；五态可正常推进；日志完整 |
| 财务记账 | 应收/应付/赔付可手工记账；台账可查 |
| 运营配置 | 通告可配置起止时间；成交动态可审核发布 |
| 数据脱敏 | 前台不暴露供应商真实信息；成交动态不含价格 |

| 兼容性 | 主流浏览器正常访问；移动端可基本操作 |

## 11. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| 缺少日常运营导致首页信息陈旧 | 中 | 明确运营清单与责任人；工作台提示「今日参考价未更新」 |
| 成交动态引发信息联想 | 高 | 粗粒度区域 + 人工审核发布 + 禁止展示价格 |
| 过期报价积压 | 低 | 定时任务自动标记超时报价为「已过期」 |
| 视觉风格调整影响使用习惯 | 低 | 全量切换前安排短周期内部试用 |
| 供应商信息脱敏不彻底 | 高 | 发布前代码审查 + 测试用例覆盖 |
